# Map view (#97)

The Map screen shows the figures in `facts` on a map of India, so a reader sees at a glance
where the coal is and who produces it. Every value is a stored fact with a link to its source
page. Nothing on the map is generated by the model.

## What it shows

| Figure | Drawn as | Where the numbers come from |
| --- | --- | --- |
| Coal resources (Total / Measured / Indicated / Inferred) | states shaded light → dark | `facts` rows with `metric = coal_resource` and a `state` (National Coal Inventory, Ministry of Coal annual report) |
| Coal production, offtake, coking coal production | a circle per company at its headquarters, area ∝ value | `facts` rows with `subsidiary` in ECL, BCCL, CCL, NCL, WCL, SECL, MCL, NEC, SCCL |

- **Period:** the newest period with figures by default. The picker lists every period that
  has figures. Resource periods read "as on Apr 2024" (a stock); production reads "Dec 2024".
- **Shades:** 5 steps by quantile, not equal widths. State resources range from under 1,000 MT
  to about 1,00,000 MT, so equal steps would paint almost every state the lightest shade. The
  legend prints each step's range. Grey means no figure.
- **Click** a state, circle or row: value in MT, the cell as printed in the source,
  verified / not verified, rank, and a link that opens the document viewer on that page.
- Anyone who can use Ask can open it (`ask_questions`): it's the same data the NUMERIC Q&A
  route answers from.

## Which facts are used

`GET /map/figures?metric=&category=&period=` (`backend/app/api/map.py`,
`backend/app/services/map_figures.py`) follows the NUMERIC route's rules:

- only documents in the user's org units (`scope_to_user`)
- never `REJECTED` facts, or values whose unit couldn't be converted (`value_std` null)
- no facts without a period (the map couldn't say which period they belong to), and no
  year-to-date figures (their "2024-12" would read as the month of December)
- several facts for one place and period: verified beats unverified, then higher confidence
- CIL, INDIA and CAPTIVE are totals, not places, so they get no circle

## Boundaries

`indiaStates.ts` is built from DataMeet's `States/Admin2` shapefile
(https://github.com/datameet/maps, CC BY 4.0), which follows Survey of India boundaries
(including Ladakh and Telangana). The credit is shown under the map; keep it there. To
rebuild (only when boundaries change):

```bash
# download States/Admin2.{shp,shx,dbf,prj,cpg} from github.com/datameet/maps first
npx mapshaper Admin2.shp -simplify 1.5% keep-shapes -o india-states.json format=geojson precision=0.001
python scripts/build_india_map.py india-states.json
```

Don't use `-filter-slivers`: it deletes Lakshadweep.

## Depth

The National Coal Inventory prints each state's resources by depth from the surface in
Table II, "State-wise and depth-wise resource of Indian coal" (pages 19-21 of the 2025
edition). The Map screen uses it in two places:

- **Depth picker** (coal resources only): shade states by one band. Depth figures have their
  own period (the 2025 inventory, as on Apr 2025), so the period picker switches with it.
- **By depth** in the side panel: the clicked state's bands, or all India when nothing is
  selected, each bar split into Measured / Indicated / Inferred, with a link to the page.

Bands are 0-300, 300-600 and 600-1200 m. Jharia coalfield is printed only as 0-600 m (it has
no 0-300 / 300-600 split), so Jharkhand has a fourth band, and the map notes that Jharia is
missing from the 0-300 and 300-600 views.

### How it is read (`backend/worker/depth.py`)

- From the PDF's **text layer**, line by line, not from the extracted tables: PyMuPDF's table
  finder dropped West Bengal's rows (page 11 of the 2025 edition came through as a header
  only) and runs other rows together.
- Handles the PDF's quirks: names run into the coal type ("MADHYA PRADESHMEDIUM COKING"),
  cut short ("ARUNACHAL PRADHigh Sulphur"), a total wrapped onto the next line, and the
  Tertiary rows' extra Inferred (mapping) column.
- **Checks:** a row is kept only if Measured + Indicated + Inferred = Total; a block (one
  state and coal type) only if its bands add up to its total row. "0-600" after 0-300 and
  300-600 is a block total; Jharia's "0-600" among other bands is a band; the sums decide.
- Stored in `depth_resources`, one row per printed line with its cells as printed, page and
  line position. Not in `facts`: these rows split a state's total, so Q&A, reports and the
  validation rules would otherwise add them in.
- Runs during ingestion. For a document processed before this existed:
  `python -m worker.depth <document id>` (leaves its facts and review decisions alone).

### Adding up (`backend/app/services/depth_figures.py`)

A state's bands are its printed "TOTAL FOR <state>" rows; a state with one coal type has no
such block, so that type's rows are used. Assam is printed in both the Gondwana and Tertiary
sections, and the two are added. All India is the GRAND TOTAL block. Block totals
(0-1200) are never added, only bands. On the 2025 inventory the 15 states add up to
4,00,715.45 MT, the printed grand total.

## Not possible with this data

A borehole cross-section (rock layers, seam thickness, grade at a GPS point) needs CMPDI's
borehole logs, which aren't in the documents. The inventory only gives tonnes per depth band.
